如何挑选：三条筛选标准先读这段

作品集的评价标准不是"会多少种算法"，而是能否把一个算法做对、做透、并诚实说明它的边界。建议按下述三条筛选。

  1. 有可验证的正确性。优先选能用参考解对照的方向（Cornell box 的 GI 收敛、能量守恒测试、白炉测试 white furnace test）。能被验证的效果，才讲得清对错。
  2. 有可视化的中间量。凡是能把中间缓冲（G-buffer、cascade 分层、探针图集、SDF 切片、方差图）直接显示出来的方向，展示价值远高于只能看最终画面的方向。
  3. 有真实的性能故事。能讲清"为什么掉帧、怎么优化、降级到什么档位"的方向，比单纯惊艳的效果更能体现工程能力。
推荐主线组合（6 个）：HDR/色调映射底座 → PBR + IBL → 阴影全家桶 → 烘焙 lightmap + SH 探针 → GTAO/SSGI → 一条深水方向（VXGI / SDF / DDGI / 实时 PT 四选一）。这六个覆盖了从底座到 GI 的完整链路，且每一环都能独立成页。

Web 端可行性红线决定技术栈选型

WebGL2 没有 compute shader

体素化、探针更新、SVGF 降噪、BVH 重建等高频数据并行任务，在 WebGL2 下只能用多 pass 片元着色器或 CPU 兜底。结论：VXGI / DDGI / 实时 PT 这三个方向应直接上 WebGPU，不要在 WebGL2 上硬做。

Web 端没有硬件光线追踪

不存在 DXR / Vulkan RT 的等价物。所有"路径追踪"都是 GPU compute 软件光追 + BVH，帧率受限，必须靠累积或离线烘焙。宣传时措辞要准确，否则会被内行一眼看穿。

3D 纹理可用但代价不同

WebGL2 支持 TEXTURE_3D，但采样开销与显存占用都更敏感；辐照度体积、froxel 雾、SDF 都能做，但分辨率要保守（如 64³–128³）。WebGPU 下余量更大。

移动端瓶颈在带宽而非算力

ray march 一律半分辨率起步、MRT 控制在 2–3 张、后处理 pass 合并、开启 KTX2 / Basis 与 ASTC 压缩、DPR 上限设 2。移动端档位应默认回落到烘焙方案。

WebGPU 覆盖要实测

桌面 Chrome / Edge 与多数 Android 已可用，iOS 与部分旧设备仍需逐版本核验。每个 WebGPU demo 都应配备 WebGL2 或烘焙结果的降级路径，并在页面显式标注。

精度与噪声

WebGL2 默认缺 float 线性过滤与部分浮点渲染目标支持，需核对扩展；半精度累积会引入条带。TAA/累积类算法建议优先在 WebGPU 上做，并用抖动 + 蓝噪声缓解。

Demo 卡片规格每个 demo 必备的八块内容

统一规格是作品集专业度的直接体现。建议做成可复用的页面模板，所有 demo 共用同一套 HUD、控制面板与文档结构。

  1. 一句话问题陈述——这个 demo 解决什么、为什么难。放在标题正下方，两行以内。
  2. 算法概要——3–5 句 + 关键公式（用 KaTeX 或预渲染公式图），说明输入、输出与核心假设。
  3. 实时画布——可全屏；提供至少 2 个预设视角与 1 个自动巡航；鼠标/触控/键盘三种操作都可用。
  4. 交互控制面板——滑块 + 开关 + 预设；状态序列化进 URL query，可直接分享复现。
  5. 中间量可视化——把 G-buffer、cascade 分层、探针图集、SDF 切片、方差图等调试视图做成下拉项。这是最能体现"我真的做了"的部分。
  6. 性能面板——帧时间（ms）、各 pass 耗时分解、draw call、显存占用、当前分辨率缩放与质量档位。
  7. 局限与已知问题——诚实列出失效案例（屏幕外信息缺失、漏光、时域拖影、漏采样）。这是拉开差距的一项。
  8. 源码与参考——核心 shader 片段链接、论文/博客出处、数据集与资产来源。

首页卡片应包含：封面 GIF（3–5 秒循环，展示参数变化过程）、标题、一句话陈述、三个标签（层级 / 技术栈 / 实时或烘焙）、一个关键指标（如「1 spp 起始 · 收敛至 512 spp · 桌面 60 FPS」）。

工程加分项体现工程能力而非炫技

性能剖析与自适应

GPU 计时（WebGL2 的 EXT_disjoint_timer_query_webgl2 / WebGPU timestamp-query）；帧时间反馈控制分辨率缩放与质量档；长帧归因到具体 pass。

多级降级路径

WebGPU → WebGL2 → 烘焙静态结果 → 预渲染视频/截图。每级明确"损失什么"，并在页面显式标注当前所处档位。

资产流水线脚本化

GLTF + Draco/meshopt 几何压缩、KTX2/Basis 纹理压缩、HDR → PMREM 预处理；烘焙器做成 Node CLI，产物入库、可复现、有版本号。

视觉回归与性能门禁

Playwright 截图对比（阈值化 diff）+ 固定 seed 的确定性随机 + FPS 阈值断言，接入 CI。这一项最能证明工程素养。

共享基础设施

monorepo 下拆分 demo，共用 HUD、控制面板、性能采集、截图工具；shader 变体管理与编译缓存；统一的相机与场景加载器。

移动端与无障碍

触控相机、DPR 上限、帧率上限、内存预算；键盘可达的参数面板、aria 标注、尊重 prefers-reduced-motion。
